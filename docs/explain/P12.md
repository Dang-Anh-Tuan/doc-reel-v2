# P12 · Nền web quản trị (W1)

## Quyết định chính
- Một process, một port: Vite build vào `static/admin`, Spring phục vụ; dev dùng proxy `/api` → :8080 nên không cần CORS.
- `AdminSpaController` chỉ khớp route có **đoạn cuối không chứa dấu chấm** (`/admin/{a:[^.]+}`, tối đa 4 cấp) → `forward:/admin/index.html`. Đường dẫn giống file (`/admin/assets/x.js`) rơi xuống resource handler → thiếu file thì 404 ProblemDetail, không bao giờ trả HTML thay JS.
- `GET /api/system/check` → `SystemCheckController` → `SystemCheckService` → `SystemSelfCheck.lastReport()` (kết quả gần nhất, rẻ). `?refresh=true` mới chạy lại các mục. Mức chung = mục xấu nhất.
- `client.ts`: mọi lỗi thành `ApiError {kind, status, title, detail, errors[], problem}`; `kind` = `http` (đọc ProblemDetail), `network` (fetch ném), `unexpected` (JSON hỏng). AbortError ném lại nguyên để hook bỏ qua.
- `useQuery(key, fetcher, {refreshSeconds})`: hẹn giờ bằng `setTimeout` **sau khi request xong** (không `setInterval`) → không chồng request khi server chậm; unmount/đổi key → abort + xóa timer; lỗi giữ `data` cũ.
- Thẻ **Hệ thống** đọc `/api/system/check` mỗi 60 s: xanh OK, vàng WARN, đỏ CRITICAL hoặc mất kết nối; bấm mở danh sách mục + "Tải lại".
- `AdminSpaIT` dùng `index.html` fixture trong test resources → chạy được khi `-Dskip.web` / chưa build web.

## Trade-off
- Regex theo số cấp thay vì `/**` + tự kiểm tra file: đơn giản, an toàn cho asset; đổi lại route sâu > 4 cấp phải thêm mẫu.
- Không thêm React Query / testing-library: hook ~60 dòng đủ cho nhu cầu; test hook bằng `createRoot` + `act` + fake timers.
- Thẻ hệ thống không chạy lại self-check mỗi lần gọi: dữ liệu có thể cũ tối đa 15 phút, bù bằng nút tải lại phía server (`refresh=true`) khi cần.
- Build web trong `generate-resources` (đề xuất ở NEEDS) làm `mvn package` chậm hơn ~30 s; bỏ qua bằng `-Dskip.web`.

## 3 câu hỏi phỏng vấn
1. Vì sao SPA cần fallback và tại sao không fallback mọi 404? Router chạy ở trình duyệt nên F5 tại `/admin/jobs/1` server phải trả `index.html`; nhưng nếu asset thiếu cũng trả HTML thì trình duyệt nhận HTML với MIME JS → lỗi khó hiểu và bị cache sai. Nên chỉ fallback đường dẫn không giống file.
2. `setInterval` vs `setTimeout` lặp khi poll? `setInterval` bắn kể cả khi request trước chưa xong → chồng request, kết quả về sai thứ tự. `setTimeout` sau khi xong + AbortController khi unmount tránh cả rò rỉ lẫn setState sau unmount.
3. Vì sao lỗi API nên là một kiểu (`ApiError`) thay vì `Error` thường? UI hiển thị thống nhất `title` + `detail`, form map `errors[]` vào từng trường, và phân biệt được lỗi mạng (thử lại) với lỗi 4xx (người dùng sửa).
