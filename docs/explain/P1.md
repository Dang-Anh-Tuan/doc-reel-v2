# P1 — Kiểm tra kịch bản (UC2)

## Làm gì
`ScriptParser.parse(byte[])` đọc JSON → `VideoScript`, trả `Result<VideoScript, List<FieldError>>`.
Mỗi `FieldError` có đường dẫn trường (`scenes[8].answer`, `$` nếu JSON hỏng). `ScriptParser.contentHash()` là SHA-256 của nội dung, bỏ `origin`.

## Quyết định chính
- **Hai tầng lỗi**: Jackson bắt lỗi cấu trúc (trường lạ, `type` lạ/thiếu, sai kiểu, enum sai, key trùng, rác phía sau) và dừng ở lỗi đầu tiên; `ScriptValidator` chạy sau và gom TẤT CẢ lỗi ràng buộc.
- **Không dùng Bean Validation (annotation)** dù SPEC nhắc: cần đường dẫn dạng `scenes[8].answer` và luật chéo (số cột, highlight, scene đầu/cuối) nên viết tay một chỗ cho dễ test và khớp validator phía web (P14). Đổi lại, phải tự viết kiểm độ dài.
- **Đếm theo code point** (`codePointCount`), chữ có dấu = 1, emoji = 1.
- **`id` scene** chỉ cho `[A-Za-z0-9_-]`, vì dùng làm tên file `work/{jobId}/<id>.png` (chặn `../`).
- **contentHash**: chuyển record → cây JSON → Map sắp key, bỏ `null` và `origin` → SHA-256. Đổi thứ tự key hay `origin` không đổi hash; đổi 1 ký tự narration thì đổi.
- `Result` đặt ở `common` để `script` chỉ phụ thuộc `common` (ArchUnit).
- Hợp đồng dùng chung: `samples/invalid/*.json` + `expected.json` (path lỗi, đúng thứ tự); web P14 test cùng bộ mẫu.

## Trade-off
- Lỗi cú pháp chỉ báo được 1 lỗi/lần, nhưng người dùng sửa xong thường thấy tiếp lỗi ràng buộc ngay lần sau.
- `theme` là String (không enum) để báo lỗi kèm danh sách theme thay vì lỗi Jackson khó đọc.

## 3 câu hỏi phỏng vấn
1. *Vì sao trả `Result` thay vì ném exception?* — Dữ liệu sai là kết quả bình thường, cần trả nhiều lỗi cùng lúc cho người sửa; exception chỉ cho lỗi bất ngờ.
2. *Làm sao hash không đổi khi đổi thứ tự key?* — Chuẩn hóa (canonicalize): sắp key, bỏ trường tùy chọn, rồi mới băm; kết hợp `topicId:version` thành khóa idempotency + unique constraint trong DB.
3. *Vì sao đếm bằng code point, không `String.length()`?* — `length()` đếm đơn vị UTF-16: ký tự ngoài BMP (emoji) = 2. Code point sát ký tự người thấy hơn; còn sót: chữ viết dạng tổ hợp (NFD) đếm 2, nên có thể chuẩn hóa NFC trước khi đếm nếu cần.
