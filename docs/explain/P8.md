# P8 — Giọng đọc + phụ đề

## Quyết định chính
- `TtsProvider` là interface (`remainingChars`, `synthesize`, `voiceKey`); `TtsService` không biết ElevenLabs hay edge-tts → thêm Azure sau không phải sửa service.
- Chọn provider **một lần cho cả video**: còn quota ≥ `needed × 1.1` (so sánh số nguyên `remaining*10 >= needed*11` để tránh sai số double) → ElevenLabs, không thì edge-tts.
- Hết quota giữa chừng (401 `quota_exceeded` / 429) → xóa audio scene, đọc lại **toàn bộ** bằng edge-tts. Lỗi mạng/5xx → `TtsTransientException`, để pipeline retry, không đổi provider.
- Đọc từng câu → cache `work/tts-cache/{sha256(provider+voice+speed+câu)}.mp3` → retry không tốn quota, đổi giọng thì tự miss cache.
- Phụ đề dựng từ thời lượng từng câu (ffprobe), không cần API căn giờ. Câu dài tách thành cue ≤ 2 dòng, nối liền thời gian. `spoken` khác `narration` → phụ đề vẫn hiện `narration`, chia giờ theo tỉ lệ độ dài.
- edge-tts: ghi câu ra file UTF-8 rồi `--file`; tham số `--rate=-10%` dạng một mảnh vì argparse hiểu `-10%` là cờ. Nghỉ 300 ms giữa các lần gọi.
- `Lexicon`: một regex gộp, thay một lượt (đầu ra không bị thay lại), chỉ thay nguyên từ, từ dài thắng; tự tải lại khi `lastModified` đổi; file hỏng thì giữ bản cũ.
- Test không cần ffmpeg: `AudioTool` là interface, bản giả 1000 byte = 1 giây. Bản thật (`FfmpegAudioTool`) có test `@Tag("media")`.

## Trade-off
- Cache theo câu: tiết kiệm quota nhưng ngắt ngữ điệu giữa câu cache và câu mới (ElevenLabs bù bằng `previous_text`/`next_text`).
- Bỏ audio ElevenLabs đã đọc khi hết quota là mất vài trăm ký tự quota, đổi lại không bao giờ trộn giọng.
- Cộng `tts_usage` sau mỗi câu thành công (không trong transaction của job) → có thể đếm dư khi job fail, chấp nhận vì dùng để thống kê/pre-check.

## Câu hỏi phỏng vấn
1. **Vì sao đọc từng câu thay vì cả đoạn?** Để có thời lượng từng câu → phụ đề chính xác không cần forced alignment, và cache/retry theo câu. Gợi ý: nêu thêm chi phí nhiều request + xử lý ngữ điệu bằng previous/next text.
2. **Làm sao đảm bảo một video chỉ một giọng khi provider hỏng giữa chừng?** Phân loại lỗi: quota → fallback toàn bộ (xóa output), transient → retry cùng provider, cấu hình sai → không retry. Provider đã dùng lưu vào job để retry giữ nguyên.
3. **Test thế nào khi không có API key / edge-tts?** WireMock cho HTTP (kể cả scenario 503 → 200), process giả (JVM con) cho exit ≠ 0 / treo / file rỗng, `AudioTool` giả cho thời lượng. Gợi ý: cố ý dùng process thật để kiểm timeout và exit code thật.
