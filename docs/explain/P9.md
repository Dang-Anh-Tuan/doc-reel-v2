# P9 · Ghép video (UC1)

## Quyết định chính
- `TimelinePlanner` là logic thuần: d_i = thời lượng audio, clip i dài d_i + T (frame cuối d_i), offset xfade thứ k = Σ d trước. `quiz` có 2 audio → 2 frame.
- `FfmpegCommandBuilder` chỉ dựng `List<String>` (không chạy) → test snapshot chuỗi lệnh, không cần ffmpeg.
- `VideoAssembler`: ffprobe từng audio → planner → builder → `ProcessRunner` (timeout 20 phút).
- Mỗi ảnh: `scale` 1.5x rồi `zoompan` (d = round(clip × fps), zoom nhẹ tới 1.06) → `xfade` nối chuỗi; audio `concat` (không crossfade) → hình scene k bắt đầu đúng lúc audio scene k.
- Phụ đề burn bằng filter `subtitles`; chạy ffmpeg với thư mục làm việc = thư mục .srt và truyền tên file tương đối → tránh escape `C:\` trong filter.
- Package `video` độc lập, không phụ thuộc `script`: nhận `SceneMedia` (ảnh + audio), phase sau tự ghép.

## Trade-off
- Zoompan trên ảnh phóng 1.5x chậm (~25s/video test 3 scene) nhưng đỡ giật; đổi lại tốn CPU.
- Thời lượng đo bằng ffprobe thay vì tin cấu hình → đúng thực tế, thêm 1 process/scene.
- Offset giữ số thực, clip làm tròn theo frame → sai lệch tối đa ~1 frame, test chấp nhận 1 frame.

## 3 câu hỏi phỏng vấn
1. Vì sao clip dài d_i + T? Xfade ăn T giây cuối clip trước nên clip phải dài thêm T để phần audio còn nguyên; xfade rơi vào đoạn lặng cuối 0,4s nên không cắt lời.
2. Làm sao test lệnh ffmpeg không cần cài ffmpeg? Tách builder thuần chuỗi + snapshot; chỉ IT gắn `@Tag("media")` mới chạy ffmpeg thật.
3. Làm sao kiểm mốc đổi cảnh tự động? Dùng PNG đơn sắc, xuất mỗi frame ra 1 pixel RGB, tìm frame đầu tiên màu trội đổi (giữa xfade = offset + T/2), so với kế hoạch ± 1 frame.
